# Modding Factory Tour

Everything in the factory layer is data. Items, recipes, machines, logistics pieces, technologies, ores and threats
are `.parkobj` objects of `objectType: "factory_prototype"`, so a mod needs no C++. Plugins can then read and steer
the factory through the `factory` script API. The built-in content is generated by
`scripts/factory-tour/gen-placeholder-art.py` into `data/factory/objects/`, which makes a good set of examples.

## The object file

A `.parkobj` is a zip holding `object.json` and the images it names.

```json
{
    "id": "examplemod.factory_prototype.heavy_turret",
    "authors": ["Example Modder"],
    "version": "1.0",
    "sourceGame": "custom",
    "objectType": "factory_prototype",
    "properties": { "kind": "machine", "machineKind": "turret", "...": "..." },
    "images": [{ "path": "images/m_d0_f0.png", "x": -32, "y": -12 }],
    "strings": { "name": { "en-GB": "Heavy turret" } }
}
```

Common properties, for every kind: `kind`, `price`, `removalPrice` (negative is a refund) and `clearance` (height in
8-unit steps). Objects refer to each other by identifier (`"ammoItem": "factory-tour.factory_prototype.bolt_magazine"`).
References resolve after load, so a mod may depend on built-in content or on another mod.

**Images must use the OpenRCT2 palette.** Objects are imported in "standard" mode: any opaque pixel that is not an
exact palette colour becomes transparent. Snap your art to the palette, as the generator's `snap_image` does. Image
offsets are relative to the tile's centre at ground level.

## Kinds

| Kind | Properties | Images |
| --- | --- | --- |
| `item` | `stackSize`, `fuelTicks` (burner fuel), `fluid`, `marketPrice`, `marketSaturation`, `shopItem` (a ShopItem name such as `factory_model`, sold from the Warehouse) | icon (24x24), belt sprite |
| `ore` | `item`, `defaultAmount` | ground overlay (64x32), icon |
| `recipe` | `ingredients`, `results` (`[{ "item": id, "count": n }]`), `timeTicks` at speed 1.0, `category` | none |
| `machine` | `machineKind` (`drill`, `furnace`, `assembler`, `boiler`, `engine`, `pump`, `lab`, `turret`), `energy` (`electric`, `burner`, `fluid`, `none`), `speedQ8` (256 = 1.0), `powerUsage`, `powerOutput`, `inputSlots`, `outputSlots`, `recipeCategories`, `miningRadius`, `miningTimeTicks`, `size` (square footprint), `frames`, `rotations` (1 or 4), `pollution`, `noise` (30 or more clanks), `photogenic`, `smoke`, `fluidBoxes`, `inputFluid`, `outputFluid`, `fluidRate`, `health` (0 = indestructible) | `[(direction * frames + frame) * size² + slice]`, frame 0 idle |
| turret machines | `turretRange` (tiles), `turretDamage`, `turretCooldownTicks`, `shotsPerAmmo`, `ammoItem` | as machines; frame 1 is drawn while firing |
| `belt`, `undergroundBelt`, `splitter` | `speed` (12 = 15 items/s), `frames`, `reach` (undergrounds) | see `FactoryPrototypeObject.h` |
| `inserter` | `swingTicks`, `frames`, `reach` | `[direction * frames + frame]` |
| `container` | `slots`, `rotations`, `warehouse`, `exportDepot` | one or four |
| `pole` | `wireReach`, `supplyRadius` | one |
| `pipe` | `capacity` | 16, by connection mask |
| `technology` | `prerequisites`, `packs` (consumed per unit), `units`, `unitTicks`, `unlocks` (factory prototypes), `rideEntries`, `sceneryGroups` | optional icon |
| `threat` | `health`, `speedQ8` (world units per tick, 256 = 1), `damage`, `attackTicks`, `frames` | `[viewDirection * frames + frame]` |

A technology locks everything it unlocks while it is loaded and unresearched. That covers ride objects and scenery
groups as well as factory prototypes, so one tree can gate both the factory and the park.

## Shipping a turret

`docs/examples/heavy_turret/` is a complete mod: a 900-health turret with a nine-tile range that fires the built-in
Bolt magazines.

1. Copy the folder and change `id` (use your own prefix), `authors` and the name.
2. Zip it so `object.json` sits at the root of the archive:
   `cd heavy_turret && zip -r ../heavy_turret.parkobj object.json images`.
3. Put `heavy_turret.parkobj` in the `object` folder of your OpenRCT2 user data and restart, or run
   `openrct2 scan-objects`.
4. In the scenario editor's Object Selection, open the factory page's Machines tab and tick "Heavy turret". To gate
   it behind research, list its identifier in a technology's `unlocks`.

## Scripting

The `factory` global (see `distribution/scripting/openrct2.d.ts`) exposes the following:

- machine snapshots, through `machines` and `getMachine(x, y)`;
- `setRecipe`;
- the Warehouse, production and Market income;
- technologies and the research target;
- threats, through `threats`, `spawnThreat` and `damage`.

Hooks:

- `factory.machine.status`
- `factory.research.complete`
- `factory.damage`
- `factory.threat.spawn`
- `factory.threat.despawn`
- `factory.turret.fire`

All changes go through game actions (`factory*` in `context.executeAction`), so plugins work in multiplayer.
`docs/examples/threat-waves.js` sends monthly waves of crawlers. Built-in threats only walk straight at the nearest
machine. Pathing, waves and AI are left to plugins.
